# 채용 수요·지역·역량 추세 데이터

**v1.1.0** · `GET /api/v1/market`는 가져온 실제 채용공고를 집계합니다. `?jobId=직무ID`는 게시된 매핑에서 검토한 채용 직종코드, 정확한 직무명 또는 확인된 요구역량 2개 이상의 일치로 관련 공고를 고릅니다. 일반 반입 직무의 명시 코드와 NCS 일치도 지원합니다. 공백·대소문자와 기술명 별칭은 정규화하며 같은 역량의 중복 표기는 한 번만 셉니다.

공공 직업상세 `jobCd`를 채용 `jobsCd`와 같다고 가정하지 않습니다. 가공 직무는 관리자가 별도로 검토한 `jobCodes`만 채용 코드 연결에 사용합니다. 코드 접두어나 제목 일부가 비슷하다는 이유만으로 연결하지 않습니다.

## 집계 기준

- `source.synthetic=true` 또는 `source.kind=synthetic`인 합성 공고는 포함하지 않습니다.
- 마감일이 한국 시간 기준 오늘 이후이거나, `채용시까지`·`상시채용`처럼 계속 모집임이 명시된 공고를 포함합니다.
- 마감일이 없거나 읽을 수 없는 공고는 `excludedUnknownDeadline`에만 집계하고 수요 계산에서 제외합니다.
- 같은 원문 URL을 여러 커넥터로 가져와도 한 공고로 셉니다. URL이 없으면 레코드 ID를 사용합니다.
- 지역은 원문의 쉼표·세미콜론·파이프 구분 값을 사용합니다. `서울`과 `서울특별시`를 임의로 합치지 않습니다. 한 공고가 여러 지역을 모집하면 각 지역에 한 번씩 포함되므로 지역별 합은 전체 공고 수보다 클 수 있습니다.
- 급여는 최대 20개의 공개 원문과 출처 링크를 표시합니다. 서로 다른 시급·월급·연봉을 섞어 평균 연봉이나 예상 소득을 만들지 않습니다.

이 통계는 기관이 수집한 공고 표본입니다. 전체 채용시장 점유율, 취업 확률, 전체 지역의 기회 규모를 의미하지 않습니다. 수집 범위, 직무 조건과 마감 정보를 확인하고 판단하세요.

## 요구기술의 출처

고용24 채용 목록 API에는 요구기술 목록이 없습니다. 제목·설명에서 기술을 자동 생성하지 않으며, 해당 API만 연결하면 실제 공고 수·지역·급여가 표시되어도 역량 빈도와 추세는 비어 있을 수 있습니다.

역량 빈도와 역량 기반 관련성은 `skillsOrigin=source_field` 또는 `admin_reviewed`로 확인한 자료만 사용합니다. 과거 버전의 origin 없는 자동 추론, 명시적 inferred 자료, 합성 데이터는 역량 통계에서 제외합니다. 일반 사내 공고 반입의 관리자 확인 자료와 공공 API 원천 필드를 혼동하지 마세요.

## 응답 구조

```json
{
  "totalJobs": 2,
  "regions": [{"name":"서울","count":2}],
  "skillFrequency": [{"name":"Python","count":2}],
  "trends": [{"name":"Python","current":2,"previous":1,"change":1}],
  "salarySamples": [{"title":"공고 제목","salary":"원문 급여","source":{"name":"승인 데이터","url":"https://example.org/source","synthetic":false},"url":"https://example.org/jobs/1"}],
  "sources": [{"name":"승인 데이터","url":"https://example.org/source","synthetic":false}],
  "updatedAt": "2026-09-27T00:00:00Z",
  "hasBaseline": true,
  "baselineDate": "2026-09-26",
  "excludedUnknownDeadline": 0,
  "warnings": ["수집한 실제 공고 표본의 집계이며 전체 채용시장 규모나 취업 확률이 아닙니다."]
}
```

위 숫자와 URL은 **구조 설명용 예시**입니다. 실제 API는 저장한 채용 데이터로만 값을 계산합니다. `updatedAt`은 포함된 공고 중 가장 최근 반입 시간이며, 원천 시스템의 마지막 검증 시간을 대신하지 않습니다. 포함된 공고가 없으면 빈 문자열입니다.

## 추세와 저장 스키마

채용공고 가져오기 성공 후 서비스가 시장 스냅샷을 기록합니다. 기존 `nr_records` 테이블의 `kind='market_snapshot'`, `owner_id=''`, `id='YYYY-MM-DD'`를 사용하며 날짜는 Asia/Seoul 기준입니다. 같은 날 재수집하면 그날 스냅샷만 교체하고 이전 날짜는 남깁니다.

저장 JSON은 다음 항목으로 구성됩니다.

| 필드 | 설명 |
| --- | --- |
| `version` | 스냅샷 구조 버전, 현재 2 |
| `date` | 집계 일자 |
| `capturedAt` | 실제 집계 시간(UTC) |
| `overall` | 전체 실제 유효 공고의 총수·지역·역량 빈도·출처 |
| `byJob` | 직무 ID별 동일 집계와 `criteriaHash` |
| `criteriaHash` | 확인된 역량 정책 v2·목표 직무명·직업코드·검토한 채용 직종코드·NCS 코드·요구역량 목록의 해시 |

현재 날짜보다 앞선 가장 최근 스냅샷과 비교합니다. `change`는 퍼센트가 아닌 **해당 역량을 요구하는 공고 수의 차이**입니다. 직무가 지정된 요청은 같은 직무의 이전 집계와만 비교합니다. 목표 직무명이나 요구 역량이 바뀌면 비교 기준이 달라지므로 이전 스냅샷을 사용하지 않습니다.

과거 자동 추론의 영향을 포함할 수 있는 v1 스냅샷은 v2 추세와 비교하지 않습니다. 이전 날짜의 v2 스냅샷이 없으면 `hasBaseline=false`, `trends=[]`입니다. 첫 수집에서 임의 상승률·인기도·변화 화살표를 만들지 않습니다. 수집 범위 변경이나 만료된 공고 감소도 증감에 영향을 주므로 이를 전체 시장 성장률로 해석하지 마세요.

스냅샷은 실제 데이터 수입에 따라 쌓입니다. 데이터를 수집하지 않은 날짜를 인위적으로 채우거나 외부 사이트에 자동 접속하지 않습니다. 폐쇄망에서도 정기적으로 반입한 실제 공고가 있으면 같은 방식으로 누적 비교할 수 있습니다.
